# 2026-10-18-01-vite-plus-audit.md

The Vite Plus audit of 2026-10-18, exactly as the auditing agent wrote it: every page of Vite Plus 1.3.0's own docs
(`node_modules/vite-plus/docs`) against this repository.

---

I read all 42 doc pages (guide/*, config/*, index.md, team.md) and every repo file you listed. Nothing was changed. The repo already follows most of the docs: `lint.options.typeAware` and `typeCheck` are on, the `vite-plus/prefer-vite-plus-imports` rule is set, there is one root `fmt`/`lint`/`staged` block, `vp check --fix` runs on staged files, `defaultPackage` is set, `setup-vp` is pinned by SHA with the version in a comment, Dependabot watches the Actions, the task cache is saved and restored the way github-actions-cache.md shows, tests import from `vite-plus/test`, and no tsconfig uses `baseUrl`.

## Things the repo does that the docs advise against

- **Folder as a positional argument.** The template's `dev` and `build` tasks run `vp dev .` and `vp build .`. monorepo.md says a positional folder keeps upstream Vite `root` semantics, not the working directory, and says to "Prefer `-C`" or use `defaultPackage`.
- **Explicit `input` without `{ auto: true }`.** automatic-data-tracking.md says to do this "only when you know the command's full input set". `apps/remy-auth-docs` `test:browser` lists only `dist/**` plus the test files. It has no lockfile, so a Playwright upgrade would replay a stale pass. The template's version does include `../pnpm-lock.yaml`.
- **Manual cache settings on plain `vp build` tasks.** The docs say "A standard `vp build` task does not need manual `input`, `output`, or `env`". The repo adds `output: ['dist/**']` and `input` exclusions anyway. `env: ['WORKERS_CI_COMMIT_SHA']` is fine, since Vite can't report that one itself. Low impact.
- **Redundant exclusions on `check:unit`.** It excludes `!**/node_modules/.*/**` from both `input` and `output`. automatic-data-tracking.md says `vp test` already reports Vitest's cache folders itself. Harmless but redundant.
