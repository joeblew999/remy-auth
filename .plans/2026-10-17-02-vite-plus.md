## Rules

- Vite Plus runs our tools; nothing of ours runs `vp run`. (The trial had Vite Plus calling the command line and
  the command line calling Vite Plus back: that is what broke.)
- A task runs one tool directly, visibly: no download, install, gate, second build or change detection hidden
  inside it.
- Checks never write. Fixing is `vp run fix`.
- Vite Plus's words for what Vite Plus does; ours only for what is ours. One name per thing everywhere.

## Steps

Done, each proven here (`vp run ci` whole: 247 browser checks in every language, 5 audits, a new app's 46):

1. The names, everywhere.
2. The task list once, in the package: `remyApp()` carries the tasks and one style; `remyDocs()` the docs' tasks.
3. The plain-function checks on `vp test`; Playwright only for the browser.
4. The project's own checks are one plain tool, `remy-check` (verifies; `--write` fixes, which `vp run fix` runs).
5. The browser path as tasks: `browsers`, `test:browser`, `test:audits`, `new-app`; `ci` runs them in turn.
6. The flow as scripts: `land` and `release` prepare, run `vp run ci`, then their own part; `setup` then `vp run check`.
7. Hooks through Vite Plus (`vp config`, `vp staged` before a commit, `vp run ci` before a push); npm pinned.
8. Deleted what Vite Plus replaced: the check sequence, `ci.ts`, `unchanged.ts`, `dev.ts`, the local-build test
   helpers; the gate keeps only what costs money or ships (translation, Core Web Vitals).
9. What the tasks found the command line had hidden: the origins (the build reads `remy.config.ts` itself), the
   commit in the build's stamp (an input now), the proxy a cached task needs to download (untracked).

Next:

10. The workspace layout: `apps/remy-auth`, `apps/docs`, `packages/*`, `templates/app`, `tools/new-app`; the task
    list in two scopes (the workspace's, the app's); `remy.config.ts` says where the app and the docs live.
11. GitHub: `setup-vp`, Vite Plus's task cache, `vp run <task>` per job.
12. Apps: `remy upgrade` moves an app onto the tasks (its scripts, its hooks, Cloudflare's build command).
13. The developer docs and `COMMANDS.md` describe only this; an independent review; then the owner's word to push.
